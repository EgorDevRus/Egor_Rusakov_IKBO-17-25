# Визуализатор графа зависимостей Cargo

Инструмент командной строки для построения и визуализации графа
зависимостей пакетов Rust (Cargo). Менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются: данные читаются
напрямую из sparse-индекса реестра Cargo или из текстового описания
тестового репозитория.

## Требования

- Python 3.11 или новее;
- Graphviz (`dot`) — необязательно. Без него SVG строится встроенным
  резервным рендерером.

## Быстрый старт

```bash
cd practical_2
mkdir -p out
./run.sh -p A -r examples/simple.txt -m test -o out/a.svg --ascii tree
```

Запрос к реальному реестру:

```bash
./run.sh -p serde_json -r https://crates.io -m cargo \
    -o out/serde_json.svg --ascii tree
```

Для запуска без `run.sh` можно использовать Makefile:

```bash
make demo    # примеры для нескольких пакетов и вариантов графа
make direct  # только прямые зависимости пакета (этап 2)
make check   # запуск тестов
```

## Прямые зависимости

Чтобы вывести только прямые зависимости пакета, ограничьте глубину
обхода:

```bash
./run.sh -p serde_json -r https://crates.io -m cargo \
    -o out/serde_json-direct.svg --ascii tree --max-depth 1
```

Для тестового репозитория это выглядит так:

```bash
./run.sh -p A -r examples/simple.txt -m test \
    -o out/a-direct.svg --ascii tree --max-depth 1
```

## Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `-p`, `--package` | имя анализируемого пакета (обязательный) |
| `-r`, `--repository` | URL sparse-индекса или путь к тестовому репозиторию |
| `-m`, `--mode` | режим `cargo` (по умолчанию) или `test` |
| `-o`, `--output` | имя SVG-файла (по умолчанию `dependencies.svg`) |
| `-a`, `--ascii` | вывод ASCII-дерева: `off` или `tree` |
| `-f`, `--filter` | пропускать пакеты, содержащие подстроку |
| `--load-order` | вывести порядок загрузки зависимостей |
| `--package-version` | явная версия корневого пакета (только `cargo`) |
| `--include-dev` | учитывать dev-зависимости |
| `--include-optional` | учитывать необязательные зависимости |
| `--max-depth` | ограничение глубины обхода, `0` — без ограничения |
| `--no-config` | не печатать блок параметров |
| `--version` | показать версию программы |

Перед выполнением печатается блок «ключ = значение» со всеми
пользовательскими параметрами. Некорректные значения завершают работу
с понятным сообщением об ошибке. Каталог для `--output` должен
существовать заранее; цели `make demo` и `make direct` создают `out`
самостоятельно.

## Режимы источника

### `test`

Тестовый репозиторий — текстовый файл, по одной декларации на строку:

```text
# Комментарий
A: B C
B: D
C: D E
D:
E:
```

Имена пакетов состоят из заглавных латинских букв, цифр и `_`. Все
упомянутые зависимости должны быть объявлены. Поддерживаются
разделители `:` и `->`, запятые в списке зависимостей и комментарии
`#`.

### `cargo`

Источник — sparse-индекс Cargo (`https://crates.io` или совместимый
URL). Инструмент скачивает документы индекса, разбирает требования
SemVer, разрешает транзитивные зависимости и корректно обрабатывает
циклы, yanked-релизы и недоступные пакеты.

## Результат работы

- DOT-файл рядом с изображением;
- SVG-изображение графа (Graphviz или встроенный рендерер);
- при `--ascii tree` — ASCII-дерево зависимостей;
- при `--load-order` — порядок загрузки (зависимости раньше пакета);
- сводка: число пакетов, рёбер и циклических рёбер.

## Структура

- `src/cargo_deps/` — CLI, конфигурация, граф, SemVer, источники данных
  и рендереры;
- `tests/` — модульные и интеграционные тесты;
- `examples/` — тестовые графы;
- `docs/COMPARISON.md` — сравнение с Cargo для этапов 4–5;
- `Makefile` — команды `check`, `test`, `demo`, `direct`, `clean`.

## Сравнение с Cargo

Подробный отчёт находится в [docs/COMPARISON.md](docs/COMPARISON.md).
Кратко:

- для `serde_json` состав графа и версии совпадают с `cargo tree`;
- для `regex` инструмент не учитывает features Cargo, поэтому по
  умолчанию пропускает необязательные зависимости `aho-corasick`,
  `memchr` и часть зависимостей `regex-automata`;
- Cargo не имеет встроенного экспорта графа в SVG, поэтому
  визуализация сравнивается с текстовым `cargo tree`, а DOT-файл
  отрисовывается стандартным Graphviz;
- порядок загрузки детерминирован, но не совпадает с планировщиком
  сборки Cargo: Cargo не гарантирует порядок независимых пакетов.

## Соответствие этапам задания

| Этап | Реализация |
| --- | --- |
| 1. CLI и параметры | все параметры, вывод ключ-значение, проверка ошибок |
| 2. Прямые зависимости | режим `cargo`, `--max-depth 1`, цель `make direct` |
| 3. Граф и циклы | рекурсивный BFS, фильтр, циклы, тестовый режим |
| 4. Порядок загрузки | `--load-order`, сравнение в `docs/COMPARISON.md` |
| 5. Визуализация | DOT, SVG, ASCII-дерево, сравнение в `docs/COMPARISON.md` |
